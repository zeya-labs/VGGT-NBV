# 日志使用指南

项目现已统一使用 `nbv_framework.utils.logging_utils` 管理日志，核心要点如下：

## 1. 日志初始化
- 入口脚本 `train.py` 在解析参数后调用 `configure_logging(...)`。
- Rank0 输出到控制台 + `runs/<experiment>/train_rank0.log`；其他 rank 只写 `train_rank<rank>.log`。
- `configure_logging` 会自动创建目录并设置格式：`时间 - 等级 - 消息`。

## 2. 获取 Logger
- 各模块通过 `from nbv_framework.utils.logging_utils import get_logger` 获取局部 logger：
  ```python
  LOGGER = get_logger(__name__)
  LOGGER.info("加载数据集完成")
  LOGGER.warning("图像缺失: %s", path)
  ```
- `get_logger` 返回带命名空间的子 logger，便于在日志中区分来源。

## 3. 替换 print
- `configure_logging(..., replace_print=True)` 会将内建 `print` 重定向到 logger，默认以 `INFO` 写入并附加 `[rankX]` 前缀。
- 若某脚本仍需原始 stdout，可在调用 `configure_logging` 时传 `replace_print=False`，或显式使用 `logging.getLogger(...).handlers`。

## 4. 日志等级建议
- `LOGGER.info`: 常规流程提示（加载模型、生成数据、保存结果）。
- `LOGGER.warning`: 数据缺失、随机采样降级等非致命问题。
- `LOGGER.error`: 无法继续执行的错误，例如模型权重损坏。

## 5. 查看日志
- 训练期间：`tail -f runs/<exp>/train_rank0.log` 或直接观察控制台输出。
- 多卡调试：可同时查看 `train_rank1.log` 等文件定位各 rank 状态。
- TensorBoard 日志仍在 `runs/<exp>/events.out...`，与文本日志互不影响。

## 6. 扩展与接入
- 新模块要输出日志时，统一 `get_logger(__name__)`，不再直接 `print`。
- 若需自定义 handler（如 JSON 日志、远程收集），在 `configure_logging` 中追加即可，所有模块会自动继承。

通过上述机制，可以在多进程、多 GPU 场景下获得一致、可追踪的日志信息，便于排查训练与数据问题。
